# Spex 0.1.0-rc.39

This prerelease adds runtime-owned remote receivers and resource coordination.
It does not claim production receiver deployment or live AWS qualification.

- The receiver API validates Action transport requests, applies host admission
  policy and executes through the existing scenario runtime. Production receiver
  workflows remain owned by runtime repositories.
- Shared definition handling supports inline documents, file patterns and TOML
  authoring while keeping GitHub-specific behavior outside acceptance semantics.
- Resource coordinators acquire shared/exclusive claim sets atomically. Durable
  file and MongoDB stores retain abandoned claims until verified recovery.
- Migration-testbench resource contracts bind physical claims to the canonical
  scenario and exact selected plan. Shared claims require a receiver coordinator
  and runtime-owned safety verification before release.
- `scenario validate`, `explain` and `run` accept `--resource-contract` for
  host-generated contracts. The CLI provides no bypass for shared coordination.

Existing entrypoints remain available. Resource-free private Kind stacks need
no cross-execution stack claims; execution-owned lifecycle checks still apply.

Local regression checks passed: 648 Go race tests (optional live MongoDB check
skipped in that run), 37 HTTP probe tests, and 70 Action tests against the candidate.
The resource coordinator also passed a separate disposable MongoDB replica-set
qualification. Runtime integration passed the testbench harness and validation of
its 73 Gateway Migration scenarios; those checks did not execute live migrations.

See [receiver contracts](../receiver.md) and [resource coordination](../resource-claims.md)
for trust boundaries, recovery rules and remaining integration responsibilities.
